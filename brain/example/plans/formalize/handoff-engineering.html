Ready the brain for other people to adopt

Close the gaps the first two real adoptions exposed, so a second operator can install this brain into a project already in flight and trust what it tells them.

In short

This repository is a system for keeping the reasoning behind a project — the goals, the decisions, the plans, what was learned afterwards — as plain files that a person, a diff and an agent can all read. It works for the person who built it. This work is about making it work for somebody else.

Two real projects have now adopted it. Between them they surfaced a dozen defects, none of which the system's own checks could have found, because a system that checks itself passes by construction. What is left is the difference between a tool that works in the hands that made it and one that survives being handed over.

When this is done, someone who has never seen the repository can fork it, install it into a project they are already halfway through, and have the record stay true as they work — without being taught the system first.

This serves A brain someone else can adopt without being told how.

The first hour

Clone it, copy it into a throwaway git repo without its .git, and run bin/adopt. If bin/lint and bin/doctor are not both clean on that fresh install, stop — that is the bug, and it has been the bug twice.

Then read knowledge-catalog/decisions/ in order. D0001 is the principle everything else serves; D0002 is the taxonomy; D0003 is why ids look the way they do. Twenty minutes, and nothing else will make sense without them.

The decisions that bind this

D0002
Every node belongs to one of four categories, and nothing cites a node newer than itself

No node may cite a node that is newer than itself.

D0005
Approach nodes name the goal they serve, and decisions carry a machine-readable claim

Every Approach node names at least one goal, so every lineage branch terminates in Intent.

Traps that cost us time

  • The template passes its own linter by construction. The same hand wrote

both. Self-testing proves almost nothing here; only content written for some other system finds real defects. Two adoptions found twelve.

  • sed-style patching of these scripts is treacherous. Replacing a slice

between two function definitions silently deleted a third that sat between them, and the failure surfaced two steps later as a NameError. Patch by exact anchored string, then ast.parse before running anything.

  • **A markdown paragraph that opens with **bold** will hang a naive

renderer.** The list-marker break pattern matches the leading *, the inner loop consumes nothing, and the index never advances. Require whitespace after the marker, and keep a guard that always consumes a line.

  • A hook invoked through a symlink does not know where it lives.

dirname $0/.. resolves to .git. Locate the brain from git rev-parse --show-toplevel, which is what CI does.

  • **Rebuilding a generated file and diffing it never works as a staleness

check** when the generator stamps a timestamp. Compare everything except the stamp; bin/graph-build --check is the pattern.

Verified, and not

Verified. A fresh install is 0 errors and 0 warnings. Both adoptions run clean on lint, doctor, stale and graph-build --check. The direction rule, the id-uniqueness check and the YAML hazard check have each caught a real defect in work written by the person who wrote them.

Not verified. No automated test exists for any of it — T0005 is exactly that gap. Windows is untested; the symlink needs a privilege there and the copy fallback has never been exercised. No brain has yet been used by two people at once, so every claim about teams is reasoning, not evidence.

Running it yourself

No dependencies. Every tool is stdlib Python 3 and runs from the brain root:

bin/lint          the gate
bin/doctor        is the install sound
bin/status        what is claimable now
bin/handoff       this document

Not included

  • A hosted service, a database, or any runtime. The files are the product.
  • Deadlines, consent dates, release processes, and anything else that models a
  • particular team's way of working rather than the work.
